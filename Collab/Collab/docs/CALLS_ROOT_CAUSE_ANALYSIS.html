Forensic Root Cause Analysis (Ponytail Mode)

CoLab WebRTC Calls & Video Connection Breakdown

Environment: collab-uat.resulticks.com (10.200.3.64 / 34.73.179.104) • Symptom: "Unable to reach media server" (25s Watchdog Timeout)

1. The Real Technical Problem

WebRTC audio/video calls require two distinct communication planes:

  • Signalling Plane (HTTPS/WSS on Port 443/7524): Used to authenticate and exchange session descriptions. WORKING (Responded HTTP 400 to join probe).
  • Media Plane (UDP/TCP on Ports 7531-7533 & TURN): Used to transport real-time audio/video RTP packets between browser and LiveKit. FAILED (Zero reachable ICE candidates).

2. Three Root Causes Identified & Fixed

Root Cause #1: Stale Media IP in LiveKit Configuration
LiveKit was broadcasting 10.205.11.8 instead of the real host IP 10.200.3.64. Browser attempted UDP transport to an unreachable IP.
Fixed in infrastructure/livekit/livekit.test.yaml: node_ip: 10.200.3.64
Root Cause #2: Dead TURN Domain (NXDOMAIN) in .env.teams
.env.teams configured turn.collab-uat.resulticks.com. DNS lookup returned NXDOMAIN (domain does not exist). External clients had no working fallback.
Fixed in .env.teams: TURN_URLS=turn:turncollab.resulticks.com:3478... (Resolves to 34.74.165.103)
Root Cause #3: Missing Allowed Peer in Coturn ACL
Coturn denies RFC1918 private subnets by default. Without an explicit allow rule, the relay dropped packets meant for LiveKit on 10.200.3.64.
Fixed in infrastructure/coturn/turnserver.conf: allowed-peer-ip=10.200.3.64
